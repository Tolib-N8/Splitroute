- **VPN-приложения, которые числились отключёнными**, теперь определяются правильно. Например, AIRLINK VPN публикует своё состояние под ID сессии, а не под ID из Системных настроек: Splitroute не видел его туннель и блокировал направленные в него приложения kill switch'ем.
- **«Маршруты» показывают текущую настройку**: если приложение перевели на другой выход, лента сразу ведёт туда. Раньше схема строилась по трафику за сутки и ещё долго показывала старый выход. Трафик теперь влияет только на толщину лент.
- После обновления Splitroute попросит обновить системный компонент (один раз, с паролем администратора): состояние VPN читает и он.
- Установку и обновление компонента теперь можно выполнить только с паролем администратора, даже если включено правило sudoers для Splitroute.

## Установка

Если у вас уже стоит Splitroute — он предложит обновление сам (или «Настройки → Обновления → Проверить»).

Новая установка: откройте `Splitroute-1.0.3.dmg` и перетащите Splitroute в «Программы». При первом запуске macOS заблокирует приложение без Developer ID: **Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть»**, или `xattr -dr com.apple.quarantine /Applications/Splitroute.app`.
